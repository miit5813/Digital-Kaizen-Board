# Digital Kaizen Board
 
Электронная доска кайдзен-предложений: подача, обсуждение и отслеживание предложений сотрудников по улучшению процессов. Учебный проект УрФУ.
 
Модуль рассчитан на внедрение на предприятиях разного размера (от 15 до 1000 человек) в закрытом локальном контуре. Интеграция с другими системами выполняется через REST API.
 
## Статус
 
Бэкенд в разработке. Готово:
 
- вход по логину и паролю, выдача JWT;
- защита эндпоинтов, проверка прав доступа;
- роли и права (шаблонные роли, создание своих ролей);
- документация API (Swagger).
В планах: пользователи, карточки предложений, маршрут согласования, комментарии, вложения, уведомления, дашборд.

## Запуск бэкенда
 
### Что нужно установить
 
- [Node.js](https://nodejs.org) версии 20 или выше (`node -v`);
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (на Windows нужен WSL2);
- Git.
### Шаги
 
Все команды выполняются из папки `apps/api`.
 
1. **Клонируйте репозиторий и перейдите в папку бэкенда:**
```bash
git clone https://github.com/miit5813/Digital-Kaizen-Board.git
cd Digital-Kaizen-Board/apps/api
```
 
2. **Запустите Docker Desktop** и дождитесь полной загрузки.
3. **Поднимите базу данных:**
```bash
docker compose up -d
docker ps
```
 
   В списке должен появиться контейнер `kaizen-db` со статусом `Up`.
 
4. **Создайте файл настроек.** Скопируйте пример и при желании измените значения:
```bash
# Windows PowerShell
Copy-Item .env.example .env
 
# macOS / Linux
cp .env.example .env
```
 
5. **Установите зависимости:**
```bash
npm install
```
 
6. **Создайте таблицы в базе:**
```bash
npx prisma migrate dev
```
 
7. **Заполните базу начальными данными** (шаблонные роли и администратор):
```bash
npm run seed
```
 
8. **Запустите сервер:**
```bash
npm run dev
```
 
   В терминале появится сообщение `Server listening at http://...:3000`.
 
### Проверка
 
- `http://localhost:3000/health` вернёт `{"status":"ok"}`;
- `http://localhost:3000/docs` откроет Swagger с описанием всех эндпоинтов.
## Настройки (`.env`)
 
| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `JWT_SECRET` | Секрет для подписи токенов (длинная случайная строка) |
| `SEED_ADMIN_PASSWORD` | Пароль администратора, который создаст `npm run seed` |
| `PORT` | Порт сервера (необязательно, по умолчанию 3000) |
 
Файл `.env` не попадает в репозиторий, в нём хранятся секреты. Не отправляйте его в чат и не коммитьте.
 
База данных по умолчанию доступна на порту **5433** (внутри контейнера 5432). Этот порт выбран, чтобы не конфликтовать с локально установленным PostgreSQL. Если нужен другой, измените его в `docker-compose.yml` и в `DATABASE_URL`.
 
## Учётная запись для разработки
 
После `npm run seed` создаётся администратор:
 
- логин: `admin`
- пароль: `admin12345` (или значение `SEED_ADMIN_PASSWORD`)
Этот пароль предназначен только для разработки. При внедрении на предприятии его необходимо заменить.
 
## Как пользоваться API
 
1. Выполните `POST /auth/login` с телом `{ "login": "admin", "password": "admin12345" }`. В ответе будет `token`.
2. Передавайте токен в заголовке каждого защищённого запроса:
```
Authorization: Bearer <токен>
```
 
3. В Swagger нажмите кнопку **Authorize** вверху страницы и вставьте токен (без слова `Bearer`). После этого можно вызывать защищённые эндпоинты прямо из браузера.
Коды ответов: `401` значит «не выполнен вход или токен недействителен», `403` значит «вход выполнен, но не хватает прав».
 
### Реализованные эндпоинты
 
| Метод | Адрес | Доступ | Описание |
|---|---|---|---|
| GET | `/health` | открыт | Проверка работы сервера |
| POST | `/auth/login` | открыт | Вход, выдача токена |
| GET | `/me` | вход | Текущий пользователь, его роли и права |
| GET | `/roles` | `roles.manage` | Список ролей |
| POST | `/roles` | `roles.manage` | Создание роли |
| GET | `/permissions` | `roles.manage` | Список доступных прав |
 
Полный и актуальный список всегда в Swagger: `/docs`.
 
## Роли и права
 
Права фиксированы в коде (`src/permissions.js`), роли собираются из прав и хранятся в базе. Администратор предприятия может создавать любые роли. Проверка на сервере идёт по **правам**, а не по названиям ролей.
 
Шаблонные роли, которые создаёт `npm run seed`:
 
| Роль | Назначение |
|---|---|
| Администратор | Полный доступ |
| Автор | Подаёт предложения, пишет комментарии |
| Эксперт | Видит все предложения, оценивает их |
| Координатор кайдзен | Видит все предложения и отчёты |
 
## Полезные команды
 
| Команда | Что делает |
|---|---|
| `npm run dev` | Запуск сервера с автоперезапуском при изменении файлов |
| `npm run seed` | Создание шаблонных ролей и администратора (безопасно запускать повторно) |
| `npx prisma migrate dev --name <название>` | Создать и применить миграцию после изменения `schema.prisma` |
| `npx prisma studio` | Просмотр таблиц базы в браузере |
| `docker compose down` | Остановить базу (данные сохраняются) |
| `docker compose down -v` | Остановить базу и **удалить все данные** |
 
## Если что-то не работает
 
| Ошибка | Что делать |
|---|---|
| `P1001: Can't reach database server` | Запустите Docker Desktop и выполните `docker compose up -d` |
| `P1000: Authentication failed` | В `.env` указан не тот порт или пароль; сверьте с `docker-compose.yml` |
| `port is already allocated` | Порт занят другим контейнером или программой; смените порт слева в `ports` в `docker-compose.yml` и в `DATABASE_URL` |
| `Cannot find module ...` | Выполните `npm install` из папки `apps/api`; в своих импортах всегда указывайте `.js` |
| `npm error ENOENT ... package.json` | Вы не в папке `apps/api`, перейдите в неё |
| `secret must be specified` | Не задан `JWT_SECRET` в `.env` |
| В Swagger `401` при вставленном токене | Токен скопирован с лишними символами или истёк (срок 8 часов); войдите заново |
 
## Правила работы с Git
 
Коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/): тип в начале, затем описание на русском в повелительном наклонении.
 
```
feat: добавить создание карточек предложений
fix: исправить проверку прав на списке ролей
chore: обновить зависимости
docs: дополнить инструкцию запуска
```
 
Основные типы: `feat` (новая функциональность), `fix` (исправление ошибки), `docs` (документация), `chore` (служебные изменения), `refactor` (изменение кода без смены поведения), `test` (тесты).
